### 使い勝手

- [ ] 音声入力待ちの状態が分からない問題（依頼者の指摘・保留中）
      起動後、話し出すまでターミナルに何も出ないため、利用者が何が起きているか
      認識できない。開発者なら分かるが、それに頼る作りになっている。
      なお指示書03の「表示に含めるもの」は認識テキストと沈黙マーカーのみと
      規定されているため、第3段階では意図的に実装していない

### 要求の充足に関わるもの

- [ ] 書き出される前の発話が失われる件を判断する（R-12）
      発話は「終了後2.0秒の無音」が確認されて初めて文字起こしされ、
      それまではメモリ上のバッファにのみ存在する。クラッシュ・強制終了時、
      話している最中の発話（実測で最大20〜40秒ぶん）は失われる。
      `Ctrl+C` は捕捉しているため保護されている。
      ファイル入力は再実行できるが、マイク入力は音声が残らず復元できない。
      対処案（音声の並行保存 / `TAIL_MARGIN_SEC` の短縮）はいずれも
      要求外の追加または精度とのトレードオフになるため、要否から判断が要る
- [ ] 発話区間の切り出しによる欠落を検証・対処する（R-5）
      VAD が発話と判定しなかった音声は認識処理に到達しない。小声のつぶやき、
      語尾の減衰、息継ぎ直後の立ち上がりが落ちうる。**落ちたことは出力から分からない**
      （沈黙マーカーすら入らず、単に無かったことになる）。
      `speech_pad_ms` は既定400msが効いているが、区間として検出されなかった小声には効かない。
      **音声条件で結果が大きく変わる。** Whisperへ渡した部と渡さなかった部の音量差は
      `sample/005` で 5.3dB（余裕が小さい）、`sample/006` で 26.8dB（明確に分離）だった。
      006（語尾の減衰・小声を意図的に含む）では取りこぼしが発生しなかったが、
      005 のような条件では余裕がない。録音環境に依存するため、対処の要否は継続判断
- [ ] `no_speech_threshold` による破棄を、長時間の音声で再確認する（R-5）
      破棄は AND 条件（`no_speech_prob > 0.6` **かつ** `avg_logprob < -1.0`）で、
      片方でも外れれば救済される。第4段階で実測したところ、
      `avg_logprob` が全区間で -0.23〜-0.56 と閾値から大きく離れており、
      **破棄は1件も発生していなかった**（`sample/003`, `006` の全10区間）。
      現時点で緩和の必要はない。ただし確認は最長81秒の音声に留まる。
      3分以上の音声での再確認が残っている
