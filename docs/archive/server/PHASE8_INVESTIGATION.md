# Phase 8: ハルシネーション対策とテキスト管理の再設計 - 調査報告

## 発見した問題

### 1. Whisperのハルシネーション（幻覚）発生

**現象:**

```text
🗣 Whisper出力: ゲンゴロラング ゲンゴロラング ゲンゴロラング ゲンゴロラング ...
📝 initial_prompt設定: ラング ゲンゴロラング ゲンゴロラング ゲンゴロラング ...
```

同じ単語が大量に繰り返され、正しい文字起こしができない。

**原因分析:**

1. **バッファ長の超過**

   ```text
   📥 チャンク追加: 16個目, 累積33.0秒
   📥 チャンク追加: 17個目, 累積36.0秒
   📥 チャンク追加: 18個目, 累積39.0秒  ← Whisperの推奨上限30秒を超過
   ⏱️ 文字起こし処理: 16.339秒
   ```

2. **処理遅延の影響**
   - 文字起こしに16秒かかる間に、新しいチャンクが3つ追加される（+9秒）
   - トリミング閾値（30秒）では間に合わない

3. **ハルシネーションの連鎖**
   - 無効なテキスト（ゲンゴロラング...）が`initial_prompt`に含まれる
   - 次の文字起こしでも同じパターンを繰り返す
   - ループが発生

### 2. 確定/暫定テキストの重複問題

**現象:**

```text
📝 文字起こし更新: 確定=433文字, 暫定=433文字, 安定=0
警告: 確定テキストが新しいテキストに含まれていない
```

確定テキストと暫定テキストが同じ内容になっている。

**原因分析:**

Phase 4.1 → Phase 6.6 → Phase 7.0 の変遷で設計の前提が崩れた。

#### Phase 4.1の設計（2026-01-25）

**前提:**

- 累積バッファは常に前回の内容を含む
- 前回と今回の差分を抽出して確定/暫定を区別

**動作:**

```text
前回: "これはテストです。システムを"
今回: "これはテストです。システムを構築しています。"
      ↑ 前回が含まれている（累積バッファの性質）

確定: "これはテストです。"（句点で終わり、前回と一致）
暫定: "システムを構築しています。"（まだ変わる可能性）
```

**メリット:**

- リアルタイムフィードバック
- 確定/暫定の視覚的区別
- 文脈保持

#### Phase 6.6の導入（2026-02-09）

**変更点:**

- バッファトリミング機能を追加（30秒で古いチャンク削除）
- トリミング時に暫定テキストを強制確定

**影響:**

- バッファが削除されると、前回のテキストが今回に含まれなくなる
- Phase 4.1の前提が崩れる

#### Phase 7.0の修正（2026-02-10）

**変更点:**

- トリミングタイミングを「文字起こし後」に変更
- 最新の文字起こし結果を確保してから強制確定

**残った問題:**

```text
前回: "ようこそ ゴーラング..."
[トリミング実行]
今回: "Googleの検索..."  ← 前回が含まれていない！

処理:
  elif self.confirmed_text:
      # 確定テキストが含まれていない → 認識結果が大きく変わった
      tentative = new_text  # ❌ new_textには確定テキストが含まれていない

結果:
  確定: "ようこそ ゴーラング..." (433文字)
  暫定: "Googleの検索..." (433文字)  ← 全く違う内容！
```

**根本原因:**

- Phase 4.1の差分抽出アルゴリズムは「累積バッファが前回を含む」前提で設計
- トリミング導入により、この前提が成立しなくなった
- 確定テキストが新しいテキストに含まれない場合の処理が不適切

### 3. 一般的なツールとの比較

**Google Meet / Zoom / Teams の動作:**

```text
[画面表示]
ようこそ、本日のセミナーへ。        ← 古いテキスト（変わらない）
今日はGoについて説明します。        ← 中間テキスト
Goは高速で効率的な言語です。       ← 新しいテキスト（まだ変わる）
```

**特徴:**

- 全体を1つのテキストエリアに表示
- 新しい発言は末尾に**追記**
- 古いテキストは基本的に変更されない
- トリミング（削除）は行わない
- セッション全体の履歴を保持

**現在の実装との違い:**

| 項目         | 一般的なツール | 現在の実装（Phase 7.0） |
| ------------ | -------------- | ----------------------- |
| 全体テキスト | 追記のみ       | トリミングで削除される  |
| 確定/暫定    | 視覚的区別のみ | データ構造で分離        |
| 文脈保持     | セッション全体 | 25秒分のみ              |
| トリミング   | なし           | あり（メモリ削減）      |

## 検出ロジックの不足

### text_filter.pyの制限

**現在の検出:**

```python
# 同一文字の異常な繰り返し（雑音）
counts = Counter(text)
most_common_char, freq = counts.most_common(1)[0]
if freq / len(text) > 0.7:  # 単一文字のみ検出
    return False
```

**検出できないパターン:**

- 「ゲンゴロラング」のような単語の繰り返し
- 「プログラミング言語を学びます。」の文の繰り返し

**必要な対策:**

- N-gram分析による繰り返しパターンの検出
- フレーズ単位での重複チェック

## 設計上の課題

### Phase 4.1の設計思想

**確定/暫定を分ける理由:**

1. リアルタイム性：ユーザーに即座に途中経過を見せる
2. 安定性の可視化：確定した部分と変わる可能性がある部分を区別
3. 文脈保持：句点で区切って、前回と一致する部分を確定

**前提条件:**

- 累積バッファが前回の内容を含む
- 差分抽出により確定/暫定を明確に区別できる

### トリミング導入後の矛盾

**矛盾点:**

1. **バッファは削除されるが、確定テキストは維持したい**
   - バッファ：メモリ効率のため削除（25秒でトリミング）
   - 確定テキスト：ユーザー体験のため保持（セッション全体）

2. **確定テキストとバッファの同期が取れない**
   - 確定テキスト：「ようこそ...」
   - バッファ：トリミング後は「Googleの検索...」
   - 両者が連続していない

3. **差分抽出の前提が崩れる**
   - 前回が今回に含まれていない
   - 確定/暫定の境界が不明確

## 解決の方向性

### 選択肢の比較

#### A案: 確定/暫定を維持（ロジック修正）

- 確定テキストが含まれない場合はリセット
- ❌ トリミング時に確定テキストが失われる

#### B案: 確定/暫定を廃止（シンプル化）

- 全体を暫定として扱う
- ❌ トリミング時にテキストが消える
- ❌ セッション全体の文脈が失われる

#### C案: UI上の工夫

- トリミング時に「[バッファトリミング]」と表示
- ❌ ユーザー体験が不自然

#### D案: トリミングを廃止

- バッファを無限に蓄積
- ❌ メモリ使用量が増大
- ❌ 文字起こし処理時間が増大

#### E案: 蓄積型全体テキスト ⭐ 推奨

- 確定テキストをバッファとは独立に管理
- 全体テキスト = 確定テキスト + 暫定テキスト
- トリミングされても確定テキストは保持
- ✅ 一般的なツールの動作に近い
- ✅ ユーザー体験が良い
- ✅ 実装も明確

### E案の詳細設計

**データ構造:**

```python
confirmed_text:
  - セッション開始からの全確定テキスト
  - トリミングされても消えない
  - 常に追記のみ（削除されない）
  - バッファとは独立

tentative_text:
  - 現在のバッファの文字起こし結果から確定済みを除いた部分
  - 変更される可能性がある
  - バッファの影響を受ける

displayed_text = confirmed_text + tentative_text
```

**動作フロー:**

```text
[初期]
確定: ""
暫定: "ようこそ。今日はGoについて"
表示: "ようこそ。今日はGoについて"

[安定して確定]
確定: "ようこそ。今日はGoについて"
暫定: "Goは高速です"
表示: "ようこそ。今日はGoについて Goは高速です"

[トリミング実行]
確定: "ようこそ。今日はGoについて Goは高速です"  ← 保持！
暫定: "効率的な言語です"  ← 新しいバッファから生成
表示: "ようこそ。今日はGoについて Goは高速です 効率的な言語です"
       ↑ トリミングされても消えない
```

**メリット:**

- ✅ 確定テキストはトリミングされても保持
- ✅ 暫定テキストはバッファの内容
- ✅ 全体テキスト = 確定 + 暫定（連続している）
- ✅ ユーザーは過去の発言を見返せる
- ✅ 一般的なツールと同じ体験

**実装上の注意:**

- `full_text`の計算を変更：`confirmed_text + tentative_text`
- トリミング時の強制確定は引き続き実行
- バッファとは独立して確定テキストを管理
