# 作業指示書 — 第2段階: 沈黙の記録と追加検証

## 0. この文書の使い方

この指示書は**第2段階のみ**を対象とする。
`docs/requirements.md` の全要求（R-1〜R-21）を今回で満たす必要はない。

第3段階以降の内容は、本段階の結果を見てから決定する。
**先回りして実装しないこと。**

---

## 1. 前段階からの引き継ぎ

第1段階で以下が判明した。

### 決着した事項

**固有名詞の誤認識には対策しない。**

実発話の検証で、日本語として自然に成立する誤認識（`文字起こし` → `文字を越し`）が
確認された。しかし語彙登録・後処理補正などの手段は、
「実際にはこう言ったはずだ」という推測を持ち込むため R-1 に反する。

誤認識の復元は、テキストを受け取る下流の LLM の役割とする。

→ **この段階で認識精度の改善を試みないこと。** 要求外として確定済み。

**モデルは small を使用する。** base では実用に耐えない誤認識が確認された。

### 判明した設計上の制約

**音声認識エンジンの内蔵 VAD が、沈黙の情報を消している。**

内蔵 VAD は無音区間を除去したうえで文字起こしを行うため、
沈黙の情報は文字起こし処理に到達する前に失われている。
検証では、実際には間があった箇所でセグメントが連続していた。

これは設定値の問題ではなく、処理構成の問題である。

## 2. 今回のタスク

### タスク A: 沈黙を記録できる構成への変更（R-7）

**目標とする構成:**

```text
マイク / 音声ファイル
  ↓
外部 VAD で発話区間と無音区間を判定
  ↓
発話区間のみを音声認識に渡す（内蔵 VAD は無効のまま）
  ↓
無音区間の情報は外部 VAD 側で保持し、テキストに反映する
```

要点は、**沈黙の情報を音声認識処理の外側で保持すること**。

**注意事項:**

内蔵 VAD を単純に無効化して長い無音をそのまま認識処理に渡す方法は採らないこと。
無音区間を与えると同じフレーズを繰り返し出力する既知の挙動があり、
R-1（発話に忠実であること）に違反する出力が生じる。

外部 VAD のライブラリ選定は任せる。選定理由を報告すること。

**沈黙マーカーの記法について:**

R-7 が求めるのは「沈黙があったと分かること」のみ。長短の区別は要求されていない。

記法（`...` か `[silence]` か等）はこの段階では確定しない。
検証のために暫定的な記法を用いてよいが、**暫定である旨をコード中に明記すること。**

### タスク B: 追加検証

以下を確認するための音声を用いて検証する。

| 確認項目       | 対象要求 | 内容                                               |
| -------------- | -------- | -------------------------------------------------- |
| 口ごもりの保持 | R-2      | 「えーっと」「うーん」等が出力に残るか             |
| 言い直しの保持 | R-2      | 言い直しの過程が失われていないか                   |
| 沈黙の記録     | R-7      | 実際の間が出力に反映されるか                       |
| 誤認識の発生率 | —        | 日本語として成立する誤認識がどの程度の頻度で出るか |

**検証方法:**

依頼者が用意する音声を使用する。以下を意図的に含んだものとする。

- 口ごもり（「えーっと」等）
- 言い直し（「AをBに、いや逆だ」等）
- 長い沈黙（10 秒以上）
- 技術用語

音声が未用意の場合は、**その旨を報告して待つこと。**
サンプル音声や合成音声での代替は行わない。実際の発話でなければ検証にならない。

**報告時の注意:**

誤認識を分類する際は、以下の基準で判定すること。

- **回復可能** — 意味不明語や明らかな崩れ。下流の LLM が文脈から復元できる。対策不要
- **回復不可能** — 日本語として自然に成立する。LLM も誤りと気づけない

第1段階の報告では `カラトコード` を問題として扱っていたが、
これは意味不明語であり**回復可能=対策不要**に分類される。混同しないこと。

- マイクからの入力（本段階はファイル入力のみでよい）
- 認識精度の改善（要求外として確定済み）
- 沈黙マーカーの記法の確定

## 4. 守ってほしい原則

### 4.1 要求を勝手に弱めないこと

要求を満たせない、あるいは実現が困難だと判断した場合、
**要求を書き換えたり、実現しやすい形に読み替えたりしないこと。**

理由とともに報告すること。要求を変更するかどうかは依頼者が判断する。

### 4.2 要求にないものを追加しないこと

「あると便利そう」「一般的にはこうする」という理由での機能追加は行わない。
必要だと考える場合は、実装せずに提案として報告すること。

### 4.3 段階を先に進めないこと

本段階の範囲を超える実装は行わない。
次に何をすべきか提案があれば、実装せず報告すること。

---

## 5. 完了時に報告してほしいこと

1. 採用した外部 VAD と、その選定理由
2. 沈黙の情報を保持する構成の概要
3. 検証結果
   - 文字起こしされたテキスト（原文のまま）
   - 口ごもり・言い直しが残っているか（R-2）
   - 実際の間と、出力に現れた沈黙の対応（R-7）
   - 誤認識の一覧と、回復可能／回復不可能の分類
4. 処理時間（音声の長さに対する所要時間）
5. 要求のうち、実現が困難だと思われるものと、その理由
6. 次段階への提案（実装はしない）
