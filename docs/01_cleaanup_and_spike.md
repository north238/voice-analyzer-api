# 作業指示書 — 第1段階: 不要機能の削除と認識精度の検証

## 0. この文書の使い方

この指示書は**第1段階のみ**を対象とする。
本ツールの全要求（`docs/requirements.md` の R-1〜R-21）を今回で満たす必要はない。

第2段階以降の内容は、第1段階の検証結果を見てから決定する。
**先回りして実装しないこと。**

---

## 1. 背景

このリポジトリは元々、Raspberry Pi 上で動作する音声解析 API サーバとして開発された。
Pi での性能が要求に対して構造的に不足すると判断し、
**開発マシン（Mac）上で動作するローカル CLI ツール**へ方針転換した。

拡張機能と Web UI は削除済み。転換前の状態にはタグから戻れる。

新しいツールの目的は、開発中の思考を音声で吐き出し、
**LLM に渡すための忠実なテキスト**として残すこと。

要求の詳細は `docs/requirements.md` を参照すること。**実装前に必ず読むこと。**

---

## 2. 最重要の前提: 何も直さないツールである

このツールの中核要求は「発話に忠実であること」（R-1〜R-4）。

- 言い間違い、言い直し、口ごもりを**そのまま残す**
- 読みやすさのための整形を**行わない**
- 意味を推測して補完・修正を**行わない**

読み手は人間ではなく LLM である。言い直しの過程そのものが思考の情報であり、
除去すると下流の LLM が判断材料を失う。

**このリポジトリに現存する日本語処理層（ひらがな化・数字正規化など）は、
この要求に違反する。** 動作するかどうかに関わらず削除対象である。

---

## 3. 今回のタスク

### タスク A: 不要機能の削除

以下を削除する。動作するかどうかは判断基準にしない。

| 対象                                          | 削除理由                                                          |
| --------------------------------------------- | ----------------------------------------------------------------- |
| FastAPI サーバ、WebSocket 関連一式            | ローカル単一プロセスで動作するため、通信層が不要（R-17, R-18）    |
| セッション管理                                | サーバがないため不要                                              |
| チャンク間の文脈引き継ぎ                      | 要求として明示的に不要と確定済み                                  |
| `normalizer.py`（janome によるひらがな化）    | R-3 に違反                                                        |
| `number_normalizer.py`（数字の読み変換）      | R-3 に違反                                                        |
| `translator.py`（opus-mt 翻訳）               | 要求外（R-15）                                                    |
| `inventory_parser.py`（品目抽出）             | 要求外（R-15）                                                    |
| `llm_analyzer.py`（Ollama 連携）              | 要求外（R-15）                                                    |
| Docker 関連（Dockerfile, docker-compose.yml） | Pi 向けの配布形態。ローカル CLI では不要                          |
| Raspberry Pi 向けの制約対応                   | Mac では不要。`torch==2.0.1` 固定、`float32` 強制、VAD 無効化など |

※ ファイル名は現状と異なる可能性がある。該当する責務のコードを対象とすること。

**残すもの:**

- faster-whisper の呼び出し部分（モデルのロード、文字起こし実行）
- マイク入力処理（pyaudio 等）
- VAD 関連（R-7「沈黙が分かること」に必要なため）

削除にあたっては、**何を削除したかを一覧で報告すること。**
判断に迷ったものは削除せず、理由とともに報告して指示を仰ぐこと。

### タスク B: 認識精度の検証スパイク

要求定義書 5.1 の未検証事項を確かめる。

**検証したいこと:**

技術的な固有名詞が誤認識され、かつ**日本語として自然に成立してしまう**ケースが
どの程度発生するか。

例:

```text
onnxruntime  → 温泉ランタイム   ← 日本語として成立するため、LLM も誤りに気づけない
HTML         → h7              ← 明らかに崩れているため、LLM が文脈から復元できる
```

前者が多いと、追加の要求（語彙登録や後処理など）が必要になる。
後者は許容できるため対策不要。

**作るもの:**

音声ファイルを入力として受け取り、文字起こし結果を標準出力に出す最小のスクリプト。

- マイク入力は不要（同じ音声を繰り返し試せるようファイル入力とする）
- リアルタイム表示は不要
- ファイル出力は不要
- 設定ファイルは不要
- **使い捨て前提。品質より、結果が早く分かることを優先する**

**確認事項（実装前に調べて報告すること）:**

CTranslate2（faster-whisper のバックエンド）が Apple Silicon の GPU を利用できるか。
利用できない場合、CPU 実行となり速度が問題になる可能性がある。
その場合は `mlx-whisper` など代替の選択肢も併せて提示すること。

**この段階では代替エンジンへの移行を実施しないこと。** 選択肢の提示までとする。

## 4. やらないこと

以下は第1段階の対象外。実装しないこと。

- リアルタイム表示（R-8）
- ファイル出力・記録の保存（R-11, R-13, R-14）
- 異常時のデータ保全（R-12）
- 設定ファイル（R-20, R-21）
- 沈黙マーカーの記法設計（R-7）
- CLI のコマンド体系、引数設計
- 誤認識への対策（語彙登録、後処理補正など）

最後の項目について補足する。
対策を検討するのは、**タスク B で問題の実在と規模が確認された後**である。
検証前に対策を実装すると、不要な機能が残る。

---

## 5. 守ってほしい原則

### 5.1 要求を勝手に弱めないこと

要求（`docs/requirements.md`）を満たせない、あるいは実現が困難だと判断した場合、
**要求を書き換えたり、実現しやすい形に読み替えたりしないこと。**

理由とともに報告すること。要求を変更するかどうかは依頼者が判断する。

### 5.2 要求にないものを追加しないこと

「あると便利そう」「一般的にはこうする」という理由での機能追加は行わない。
必要だと考える場合は、実装せずに提案として報告すること。

### 5.3 削除をためらわないこと

動作するコードであっても、要求に照らして不要なら削除する。
「一応残しておく」は行わない。残骸は将来の誤用の原因になる。

タグで過去の状態に戻れるため、削除によって失われるものはない。

### 5.4 段階を先に進めないこと

第1段階の範囲を超える実装は行わない。
次に何をすべきか提案があれば、実装せず報告すること。

---

## 6. 完了時に報告してほしいこと

1. 削除したファイル・機能の一覧
2. 削除を見送った項目とその理由（あれば）
3. スパイクの実行結果
   - 文字起こしされたテキスト（原文のまま）
   - 誤認識の一覧と、それぞれが「日本語として成立してしまうか」の分類
4. Apple Silicon での GPU 利用可否と、代替エンジンの選択肢
5. 要求（R-1〜R-21）のうち、実現が困難だと思われるものと、その理由
6. 次段階への提案（実装はしない）

---

## 7. 参考: 検証用音声について

依頼者が実際に話した音声を用意する。
普段の開発で使う技術用語（ライブラリ名、プロトコル名、コマンド名など）を含み、
言い直しや沈黙を含んだ、実際の利用状況に近いものとする。

音声が未用意の場合は、**その旨を報告して待つこと。**
サンプル音声や合成音声での代替は行わない。実際の発話でなければ検証にならない。
